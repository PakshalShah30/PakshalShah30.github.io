Personal project · Phase 1 of 5

Smart City Travel Planner

github.com/PakshalShah30/smart-city-travel-planner ↗

Give it a city, a starting point, and a time budget; it returns a routed day plan through real places, using real street-network travel times, that gets you back where you started before the time runs out. Picking a day out is not a sorting problem: every attraction has a location, a visit duration, an opening window, and a value to a particular person, and choosing the best subset and the best order is the Orienteering Problem, which is NP-hard.

It is also a deliberate rebuild of my own 2018 university project of the same name. That version specified three itinerary modes, route optimization, ratings, and opening-hours awareness, and shipped a two-column SQL lookup over four rows of placeholder data. This repository is the honest version of that specification, and it tracks the gap on purpose.

Trowel for Salesforce

github.com/PakshalShah30/trowel-for-salesforce ↗

An AI agent that reads a Salesforce org's metadata and produces the kind of Well-Architected assessment consultancies bill five figures for: dead automation, conflicting triggers, permission sprawl, and a prioritized remediation roadmap. The design principle is that findings are detected deterministically by dependency-graph queries, and the language model explains and prioritizes them but never discovers them, because a hallucinated finding would destroy the product's whole premise.

Currently early and paused while the travel planner takes priority. The scaffold, retrieval pipeline, and a deliberately seeded test org are in place; the parser, dependency graph, and eval suite are not yet written. Listed here because the architecture argument is worth reading, not because it is finished.
